# 05 · 研究改进与自动化（v1.2）

> 日期 2026-10-21。目标：让个人量化研究者用一套工具完成“取数 → 验数 → 回测 → 防过拟合 → 出信号 → 监控”的闭环，并且每一步都能自动化、可复现。

## 一、参考的文章与项目

| 来源 | 核心思想 | 本项目怎么用 |
|---|---|---|
| Bailey, Borwein, López de Prado & Zhu (2015) *The Probability of Backtest Overfitting*；[esvhd/pypbo](https://github.com/esvhd/pypbo) | CSCV：把时间切成 S 块，枚举一半做样本内、一半做样本外；样本内最优在样本外跌到中位数以下的比例 = PBO | `validation.pbo_cscv`（向量化实现，S=16 时 12870 种切分 < 1 秒）；稳健性页面、样本外检验报告 |
| Bailey & López de Prado (2012) *The Sharpe Ratio Efficient Frontier* | PSR：考虑偏度/峰度/样本长度后“真实夏普 > 基准”的概率；MinTRL：需要多长的记录才能确认 | `validation.probabilistic_sharpe`；回测页面验收区、A股验证报告 PSR 列 |
| Bailey & López de Prado (2014) *The Deflated Sharpe Ratio*；Harvey & Liu (2015) *Backtesting* | 试的越多，最好结果里的运气越多；必须记录试验次数 | `registry.py` 试验登记簿（`reports/试验登记.csv`），每次验证自动登记 |
| [jianweiweng05/qsx-strategy-score](https://github.com/jianweiweng05/qsx-strategy-score) | “随机择时”检验：策略是否比随机进出更好 | `validation.random_timing_test`：仓位序列整体循环平移，保留平均仓位与换手节奏，只打乱与行情的对应 —— 比“同仓位基准”更严格 |
| [Chinghu-web/quantros](https://github.com/Chinghu-web/quantros) | “证伪器而非保证书”：多道门依次证伪，最强结论只是“未被证伪” | 验收区并列展示：回撤 / 卡玛 / 同仓位 / 随机择时 / PSR，任何一道不过都如实显示 |
| [ml4t/diagnostic](https://github.com/ml4t/diagnostic) | 把统计验证做成可复用的诊断库，与回测解耦 | `validation.py`、`quality.py`、`compare.py` 都是纯函数，可单独调用和测试 |
| 软件工程：回归测试 / CI | 每次改动自动跑测试并对比基线 | `compare.py` 区分“数据变化”与“代码退化”；GitHub Actions 跑单元测试 + 演示数据流水线 |

## 二、这次改进中发现的真实问题

### 1. 数据：新浪回退数据没有复权（已修复）
新增的数据质量检查在 510500 上报出 2022-08-29 单日 −12.7%（超过 ±10% 涨跌停）。排查发现：
- 东方财富接口限流时，系统回退到新浪 `fund_etf_hist_sina`，**它返回的是不复权价格**，却被存进了 `_qfq`（前复权）缓存；
- 结果：所有 ETF 的分红都被当成“下跌”。例如 510300 历史上 14 次分红、510880 红利ETF 19 次分红全被算成亏损；
- 修复：读取新浪复权因子文件（累计份额系数 + 累计分红），按除权日精确前复权；与东方财富前复权的日收益对比误差 < 0.01%；缓存升级为 v2。

修复后：沪深300ETF 买入持有年化 3.9% → 5.6%，中证500ETF 4.6% → 6.4%（分红被找回）。

### 2. 界面：组合配置、稳健性检验两个页面会报错（已修复）
`st.form("pf")` 与 `st.session_state["pf"]` 同名，新版 Streamlit 不允许，点击按钮即崩溃。已改用独立的结果键。

### 3. 研究结论：择时优势只在部分资产上显著
修复数据后，24 组（6 只 ETF × 4 策略）的随机择时检验：

| 资产 | 随机择时 p（4 个策略） | 解读 |
|---|---|---|
| 创业板ETF、黄金ETF | 全部 ≤ 0.04 | 择时显著优于随机，趋势跟踪确有作用 |
| 国债ETF | 0.02–0.07 | 边缘显著 |
| 沪深300、中证500、纳指 | 0.12–0.54 | **不显著**：这些资产上的回撤降低主要来自“平均仓位低 + 波动率目标”，不是择时 |

对实盘的意义：在沪深300 上，“恒定 35% 仓位 + 现金”能拿到大部分风控效果，且交易少得多。

### 4. 默认参数：样本外检验否决了“熊市留 30% 仓位”
修复数据后重做（`reports/样本外检验_20261021_2211.md`）：
- C（熊市留 30%）相对 B 的卡玛差，在所有视角的 95% 置信区间都跨过 0 —— 连挑选它的样本里都不显著；
- E（熊市留 30% + 目标波动 20%）在标的外（p = 0.034）和 2020 年后（p = 0.02）**显著更差**；
- Walk-Forward 中每年挑“过去 3 年最好方案”的样本外卡玛 0.18 < 固定 B 的 0.24；PBO 中位数 38%。

**结论：保持默认 B 不变。**

## 三、自动化

| 层 | 工具 | 频率 |
|---|---|---|
| 每日信号 | `auto_run.py daily`：强制刷新行情 → 数据质量检查 → 单标的信号 + 组合建议持仓 → 与上一交易日对比列出“需要操作” → 可选推送 | 工作日 16:30（`安装定时任务.bat`） |
| 周度验证 | `auto_run.py weekly`：A股验证 + 自动对比上一份报告，区分数据变化与代码退化 | 每周五 |
| 季度监控 | `auto_run.py quarterly`：样本外检验，看策略是否衰减 | 每季度首周周五 |
| 代码质量 | GitHub Actions：单元测试（Python 3.11/3.12）+ 演示数据流水线 + 报告回归检查 | 每次推送 |
| 推送（可选） | `notify.json`：Server酱 / 企业微信 / 钉钉 / 飞书 | 跟随任务 |

刻意不自动化的：**自动调参后改默认值**（等于造一台过拟合机器）和**自动下单**（PRD 明确不做）。

## 四、后续路线图（按价值排序）

1. **组合层面去掉择时的对照研究**：真实数据上“配置不择时”卡玛 0.93 高于“风控组合” 0.65，最值得研究。
2. **参数平原扫描**：对 `bear_exposure`、`target_vol` 做连续网格，用 PBO 而不是单点比较。
3. **实盘偏差跟踪**：记录实际成交与信号的差异（滑点、未执行），量化“人”的执行成本。
4. **非幸存者标的池**：加入已退市/清盘的 ETF，消除标的外检验的幸存者偏差。
5. **固定数据快照的回归基线**：周度验证的行情每周都会延长，回归判断依赖容差；可另存一份冻结数据做严格回归。
